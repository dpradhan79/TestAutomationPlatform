# TestScriptGeneratorAgent

This is the deep agent solution to build test scripts from natural language, which can be read from external source such as JIRA, Azure DevOps.
This will have independent agents, which will act as subagents.

Solution is planned to use langchain deepagents to utilize tools, checkpoints, longterm memory, PGVector Database,Playwright, FastAPI and will be deployed on langsmith and Azure Foundry for usage.
The solution is planned for production scale usage.


## Agents

1. IntentGeneratorAgent - It will read natural language, generate set of intents as defined in schema, which will be a pydantic model. The schema will be used for respons generation in specified format.
2. StepGeneratorAgent - It will process Intents generated by IntentGeneratorAgent and will use custom tool built upon Playwright to navigate through application and will generate output based on Steps Schema, a pydantic model, ant input to agent to generate in given schema.
   The agent will use playwright to navigate to application and will use current DOM state and screenshot to generate next step/steps based on current Intent. The current step/steps schema will be used by Playwright (action, selectors, argument, parameter which are fields in Step/Steps) to perform UI action using playwright APIs, which are exposed as tool to agent.
3. ScriptAgent - It will process Steps Schema object (JSON having list of step) after all Intents have been processed by StepGeneatorAgent, will take Framework structure/metadata or readthrough Git repo,if available or provided to generate framework compatible scripts else will produce monolithic test scripts.
4. MainAgent - It should delegate tasks to subagents - IntentGeneratorAgent, StepGeneratorAgent and TestScriptGeneratorAgent in asynchronomous mode.

# Core Architecture Decisions

## MainAgent

MainAgent will be implemented using:

```python
create_deep_agent(...)
```

MainAgent is responsible for:

- Reasoning
- Planning
- Routing
- Delegation
- Tool Usage
- Memory Usage
- Checkpoint Integration

FastAPI acts only as the remote interface layer.

---

## KnowledgeAgent

KnowledgeAgent is optional.

Purpose:

```text
Requirement
      +
Retrieved Context
      =
Augmented Requirement
```

KnowledgeAgent reduces hallucination by enriching requirements using organizational knowledge.

Future sources:

- PDF
- Confluence
- JIRA
- Azure DevOps
- SharePoint
- Internal Documentation

---

## IntentGeneratorAgent

Input:

```text
Requirement
```

Output:

```python
List[Intent]
```

Responsibilities:

- Requirement Understanding
- Intent Extraction
- Intent Validation

---

## StepGeneratorAgent

Input:

```python
List[Intent]
```

Output:

```python
List[ExecutedStep]
```

Responsibilities:

- Navigation Planning
- DOM Analysis
- Screenshot Analysis
- Locator Discovery
- Browser Exploration

StepGeneratorAgent owns browser interactions.

---

## ReviewAgent

Input:

```python
List[ExecutedStep]
```

Output:

```python
ReviewReport
```

Review Areas:

- Missing Assertions
- Weak Locators
- Duplicate Steps
- Ambiguous Steps
- Confidence Analysis

ReviewAgent executes before HITL.

---

## HITL

Human Approval happens after ReviewAgent.

User can:

- Approve
- Reject
- Modify
- Add Steps
- Delete Steps

Output:

```python
ApprovedExecutionPlan
```

---

## ScriptAgent

ScriptAgent is a Renderer.

ScriptAgent does NOT:

- Open Browsers
- Analyze Screenshots
- Analyze DOM

ScriptAgent only transforms:

```python
ApprovedExecutionPlan
```

into:

```text
Framework Specific Artifacts
```

Examples:

- Selenium Java TestNG
- Selenium Java Cucumber
- Playwright Python
- Playwright TypeScript
